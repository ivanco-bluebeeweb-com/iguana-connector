# Iguana Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: интеграционный
инженер в здравоохранении на self-hosted Iguana (HL7/FHIR обмен сообщениями).

## 1. Credential type
Self-hosted: base_url (SSRF-защищённый) + admin username/password (Basic auth, судя по
описанию — уточнить по schemas.py). Дополнительно: отдельная licensing-portal учётка
(my.interfaceware.com) — ДВЕ РАЗНЫЕ системы аутентификации в одном приложении.

## 2. Идеальный флоу
1. **Первое открытие** — `Empty` с явным разделением на ДВЕ карточки/секции: "1.
   Подключить сам сервер Iguana" и "2. Подключить лицензионный портал (опционально, для
   управления лицензиями)" — не смешивать эти две формы, у пользователя часто нет
   доступа ко второй сразу.
2. **Форма сервера** — base_url + username + password (administrator), с явным
   предупреждением про типичный порт (6543) в placeholder.
3. **После успеха** — версия сервера + список каналов и их состояние (running/stopped)
   сразу — критично в здравоохранении: остановленный канал = не идут сообщения между
   системами, потенциальный клинический риск.
4. **Ошибка "self-signed cert"** — здравоохранительные self-hosted инсталляции часто
   имеют внутренние сертификаты — конкретное объяснение этого класса ошибки.
5. **Channel down alert emphasis** — если хотя бы один канал остановлен — это должно
   быть первым, что видно после подключения, не потеряно в списке.
