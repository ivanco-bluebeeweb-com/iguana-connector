# Iguana Connector — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
Интеграционный инженер в здравоохранении, использующий Iguana (от той же линейки, что и
Mirth) как self-hosted движок обмена HL7/FHIR-сообщениями между медицинскими системами.

## 2. Момент истины после подключения
Сразу после `connect_iguana` (с SSRF-защищённой валидацией self-hosted адреса через
`normalize_base_url`) — `current_version` подтверждает живое соединение, дальше сразу
видно список каналов и их состояние.

## 3. Что пользователь видит
- Каналы обмена сообщениями и их статус (running/stopped) — `list_channels`,
  `get_channel_status`.
- Логи обработки сообщений по каналу, включая ошибки — `get_channel_logs`.
- Очередь сообщений, ожидающих обработки — `list_queued_messages`.
- Версию сервера Iguana (для проверки совместимости) — `current_version`.
- Конфигурацию канала (from/to модули, трансляции) — `get_channel_config`.

## 4. Чем пользователь может управлять
- Запускать/останавливать канал — `start_channel`, `stop_channel`.
- Переотправлять сообщение с ошибкой — `reprocess_message`.
- Обновлять конфигурацию канала (трансформации, маршрутизацию) — `update_channel_config`.
- Очищать очередь зависших сообщений (destructive — необратимо) — `purge_queue`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'все ли каналы обмена с лабораторией сейчас работают?'. Она
проверяет через `list_channels` + `get_channel_status` — а если что-то остановлено,
`start_channel` включает обратно без захода на self-hosted сервер вручную."

## 6. Что делает это "заточенным под него"
Self-hosted адрес клиента проходит SSRF-защищённую проверку перед каждым использованием —
безопасно работает даже если сервер развёрнут внутри закрытого больничного контура.
